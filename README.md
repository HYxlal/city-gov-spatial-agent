# 面向城市治理的时空智能体系统

> 本科毕业设计 · 研究与实现方案
>
> 核心主张：**让每条空间结论都可被论证、可被复算。**

## 这个课题要解决什么

城市治理中的空间结论（"哪个街道事件高发""15 分钟生活圈覆盖了多少人""这片区域存在服务盲区"）一旦由大模型生成，往往只给出结论和一张图，中间的空间推理过程是不透明的——决策者只能选择相信或不信。

本课题把这件事建模成**论证问题**：智能体输出的每条空间结论，都必须能还原成一张

```
Claim（结论） → Evidence（证据） → Operation（算子与参数） → Provenance（数据源与版本）
```

的论证图，并支持一键复算校验。可溯源由此从"提示词里的软要求"变成"系统结构上的硬约束"——没有证据的结论在出口无法通过校验，会被退回重规划。

## 主攻方向

**SAG · Spatial Argument Tracing（空间论证可溯源）**

| 层次 | 内容 |
| --- | --- |
| 方法层 | SAG 四级结构，Evidence 限定为四类：网格聚合 / 几何覆盖 / 点集 / 参照对比 |
| 机制层 | `build_argument` 作为 LangGraph **独立节点**，出口做结构化校验，无证据即不合格并回退重规划 |
| 呈现层 | 论证面板：点结论 → 高亮证据图层 → 展开算子参数 → 一键复算比对 digest |

整体实现"够用即止"：单场景（12345 热线 / 城管事件时空态势研判）、6–8 个工具、8–12 个指标，精力集中在纵深层。

## 技术基线（已锁定）

- **编排**：LangChain 1.0（`create_agent` + LangGraph 运行时 + middleware），不使用 0.x 旧 API
- **数据**：PostgreSQL 15+ / PostGIS 3.4+，H3 网格作为跨源统一空间主键，pgvector 存指标字典与知识库
- **地图**：MapService 可插拔适配层，默认 provider 为高德（Web 服务 REST + JS API 2.0），坐标基准 GCJ-02；配套 Mock provider 支持无 Key 离线运行
- **模型**：主 LLM 走云端 DeepSeek，本地 Ollama 作为断网降级

## 评测设计（核心四项）

| 指标 | 目标 |
| --- | --- |
| 证据完整率 | 100% |
| 必需证据命中率 | ≥ 85% |
| 复算一致率 | ≥ 95% |
| 幻觉率 | ≤ 3% |

核心消融 **A1 = 去掉 `build_argument` 节点**，配合 10 条"不可回答探针"检验系统是否会在数据不支持时编造证据。
