# 面向城市治理的时空智能体系统

> 本科毕业设计 · 研究与实现方案
>
> 核心主张：**让每条空间结论都可被论证、可被复算。**

## 这个课题要解决什么

城市治理中的空间结论（"哪个街道事件高发""15 分钟生活圈覆盖了多少人""这片区域存在服务盲区"）一旦由大模型生成，往往只给出结论和一张图，中间的空间推理过程是不透明的——决策者只能选择相信或不信。

本课题把这件事建模成**论证问题**：智能体输出的每条空间结论，都必须能还原成一张

```
Claim（结论） → Evidence（证据） → Operation（算子与参数） → Provenance（数据源与版本）
                                        ↘ Caveat（限定条件）
```

的论证图，并支持一键复算校验。可溯源由此从"提示词里的软要求"变成"系统结构上的硬约束"——没有证据的结论在出口无法通过校验，会被退回重规划。

## 主攻方向

**SAG · Spatial Argument Tracing（空间论证可溯源）**

| 层次 | 内容 |
| --- | --- |
| 方法层 | SAG 五构件：Claim / Evidence / Operation / Provenance / Caveat（对标 Toulmin 论证模型） |
| 机制层 | `build_argument` 作为 LangGraph **独立节点**，出口做 L1–L4 四级硬校验（结构 / 数值绑定 / 方向一致 / 限定条件），不通过即回退重规划 |
| 呈现层 | 论证面板：点结论 → 高亮证据图层 → 展开算子参数 → 一键复算；拖动空间参数做 What-if 敏感性分析，实时提示结论是否翻转 |

整体实现"够用即止"：单场景（12345 热线 / 城管事件时空态势研判）、6–8 个工具、8–12 个指标，精力集中在纵深层。

## 已实现

| 目录 | 内容 |
| --- | --- |
| `src/argument/` | 主攻模块：五构件模型、L1–L4 四级校验、Caveat 规则生成、What-if 复算 |
| `sql/01_schema.sql` | 业务库：7 张表（H3 网格、事件按月分区、指标语义层），展示列与 3857 计算列分离 |
| `sql/02_sag_tables.sql` | SAG 五表 + 3 个评测视图（证据完整率、通过率可直接 SELECT 出数） |
| `data/generate_synthetic_data.py` | 固定种子合成数据，输出 CSV 与 manifest（含数据版本摘要） |
| `examples/s1_end_to_end.py` | 从数据到论证图的端到端链路，含正常/方向错/编造三类用例 |

`src/argument/` 各文件职责：

| 文件 | 作用 |
| --- | --- |
| `sag.py` | 五构件数据模型，含"每个数值必须声明来源"的模型级约束 |
| `validator.py` | L1–L4 四级出口校验（结构 / 绑定 / 语义 / 限定） |
| `expr.py` | 派生公式的 AST 安全求值——公式来自 LLM，属不可信输入，不能用 `eval` |
| `normalize.py` | 实体规范化与双向包含匹配（"朝阳区" 可匹配 "朝阳"） |
| `caveat.py` | Caveat 的规则化自动生成（降级 / 小样本 / 近似 / 边界 / 坐标基准） |
| `replay.py` | digest 复算、稳定性检查、What-if 参数敏感性 |
| `digest.py` | 结果摘要，键序无关 |

**对照实验结论**：把数值拍平成集合再找成员的做法（常见写法），在 5 条测试结论上错 2 条——误杀合法派生百分比（12.5% 不在原始字段里）、放过"数值对但说成下降"的方向冲突。本实现 0 误判。

## 技术基线（已锁定）

- **编排**：LangChain 1.0（`create_agent` + LangGraph 运行时 + middleware），不使用 0.x 旧 API
- **数据**：PostgreSQL 15+ / PostGIS 3.4+，H3 网格作为跨源统一空间主键，pgvector 存指标字典与知识库
- **地图**：MapService 可插拔适配层，默认 provider 为高德（Web 服务 REST + JS API 2.0），坐标基准 GCJ-02；配套 Mock provider 支持无 Key 离线运行
- **模型**：主 LLM 走云端 DeepSeek，本地 Ollama 作为断网降级

## 评测设计（核心指标）

| 指标 | 目标 |
| --- | --- |
| 证据完整率 | 100% |
| 必需证据命中率 | ≥ 85% |
| 复算一致率（多次独立运行 digest 稳定率） | ≥ 95% |
| 数值绑定通过率（含派生复算） | ≥ 95% |
| 幻觉率 | ≤ 3% |
| 正确拒答率（U 组探针） | ≥ 80% |

核心消融 **A1 = 去掉 `build_argument` 节点**；第二组核心对照 **A5 = 关掉确定性数值校验**（只保留结构校验），用来证明 L2 绑定层确实降了幻觉。配合 10 条"不可回答探针"检验系统是否会在数据不支持时编造证据。
